# 门店配送波次中枢

完整的波次编排与交接系统：门店需求、车辆、波次、周转箱与扫描事件，
解决"周转箱串线、改单时点不可考、重复扫描重复交接"等现场混乱。

## 能力总览

- **波次编排**（`wavehub/planner.py`）：按门店收货窗口、车辆载重与温层、
  商品共载限制、线路时长和箱筐回收任务，把截单后的需求编排成装车波次；
  编排结果确定，同一输入永远得到同一线路方案。
- **截单语义**（`wavehub/service.py`）：截单前同店同波次需求自动合并；
  截单后只有获批差异单能改变尚未封签的线路，已封签线路一律拒绝并留痕，
  回看记录即可判断改单发生在封签前还是封签后。
- **同一配送版本**：司机领单、仓库装箱、车辆封签、门店签收都引用线路的
  当前配送版本；差异单获批生成新版本，扫描按业务发生时间定位有效版本校验。
- **扫描交接**：周转箱按版本预分配到线路，跨线装车在扫描环节即被拦截；
  scan_id 与业务键双重幂等，重复扫描不会再次装车或签收；离线补传按
  业务发生时间（occurred_at）做容器时序合法性校验，被拒扫描可重传收敛。
- **并发封签**：`active_seal` 以线路为主键，线程竞争或跨连接竞争都只
  保留一个封签结果。
- **整车转派**：车辆故障后线路进入待转派，原封签作废留痕；车上容器随
  线路整体换车，已交接容器仍在门店环节逐件追踪。
- **门店查询**：`store_view` 返回商品行的计划/缺货/拆单情况、停靠进度、
  签收状态，以及缺货、拆单、延迟的具体原因。
- **恢复运行**：全部状态持久化在 SQLite，重启后 `recovery_report`
  列出待转派车辆与未回收容器当前所处的环节。

## 目录结构

- `wavehub/`：业务服务包（`planner.py` 编排引擎，`service.py` 业务门面，
  `db.py` SQLite 表结构，`errors.py` 业务异常）。
- `domain/contract.json`：实体、状态、事件类型和时间约定。
- `examples/events.json`：一段按发生时间排列的示例事件。
- `examples/end_to_end.py`：端到端示例，跑通完整波次生命周期。
- `tools/validate_contract.py`：使用 Python 标准库和 SQLite 内存表检查资料一致性。
- `tests/`：编排、截单与版本、扫描、封签并发、转派、门店查询、恢复运行的测试。

## 构建

```bash
python3 -m compileall -q .
```

## 测试

```bash
python3 -m unittest discover -s tests -v
```

## 资料校验

```bash
python3 tools/validate_contract.py
```

## 端到端示例

```bash
python3 examples/end_to_end.py
```

所有命令均在项目根目录执行，不需要启动额外服务。
